# Perfetto trace converter for gem5 AMD gpu model

This tool takes a data dump generated by a gem5 run and converts it to a trace which can be opened in [https://ui.perfetto.dev/](Perfetto).
The converter is based on [https://github.com/ihavnoid/tg4perfetto](tg4perfetto) which is designed to allow for custom perfetto formats (i.e., not generating as a typical perfetto trace is).
As of June 21st, 2025 this package is available as a [https://pypi.org/project/tg4perfetto/](pip package).

The tool is mostly useful for visualizing GPU application execution, single GPU kernel wave slot activity, or detailed single kernel/wavefront instruction timelines.
A full GPU application execution can show a timeline of when SDMA transfers occur (i.e., memcpy and friends), when AQL tasks start (kernels), and optionally custom application instrumentation using [https://www.gem5.org/documentation/general_docs/m5ops/](m5ops).
Single kernel wave slot activity is useful to visualize occupancy of the GPU and shows when dynamic wavefronts begin/end and any gaps in between.
Detailed instruction timeline can help identify "bubbles" in GPU execution.

## Installation

Just the [https://pypi.org/project/tg4perfetto/](tg4perfetto) package is required.

    ```bash
    pip install -r requirements.txt
    ```

Alternately use a virtual environment such as venv. Remember to replace the examples command below with ~/.venv/tg4perfetto/bin/python3.

    ```bash
    python3 -m venv ~/.venv/tg4perfetto
    pip install -r requirements.txt
    ```

## Usage

To start run some gem5 application with perfetto logging enabled. Follow regular gem5 process to build VEGA_X86 and the three gem5-resources used below.

    ```bash
    build/VEGA_X86/gem5.opt -d perfetto-test configs/example/gpufs/mi300.py --disk-image ~/gem5-resources/src/x86-ubuntu-gpu-ml/disk-image/x86-ubuntu-gpu-ml --kernel ~/gem5-resources/src/x86-ubuntu-gpu-ml/vmlinux-gpu-ml --app ~/gem5-resources/src/gpu/square/bin.default/square.default --use-perfetto
    ```

There should now be a file called `perfetto-test/perfetto-log.gz`. This can be used multiple times to generate various perfetto traces.

Generating a full application view. Note that if you have a short application you may have to zoom *very* far in to see anything in the [https://ui.perfetto.dev/](perfetto viewer). You can click on slices in the perfetto timeline to see various information about the slice (e.g., duration for SDMA copies, launch bounds for kernels, etc.).

    ```bash
    python3 util/amdgpu/perfetto-converter/convert.py -i perfetto-test/perfetto-log.gz -o perfetto-test/square.all.pftrace
    ```

Generating timelines for kernels of interest. In the square application above, there is one compute task which is task 2. This will be the start AQL task as well as our task of interest.

    ```bash
    python3 util/amdgpu/perfetto-converter/convert.py -i perfetto-test/perfetto-log.gz -o perfetto-test/square.task2.pftrace --start-at-aql-task=2 --task=2
    ```

## Advanced usage

The Shader() SimObject can also add instruction level details to the trace, but this must be explicitly enabled by setting the `use_perfetto_insts` bool to True. You can use commands similar to above. Note that there is a limit to the amount of information that can be viewed on perfetto, so you will likely have to limit the output to a specific kernel.

In the future a specific tick range could be added to the converter script to allow for longer running kernels.
